# 登录验证码接入

默认登录页通过服务端签发验证码，再将挑战 ID 和用户输入提交到登录接口。接入此版本时需要同步提供后端接口；验证码尚未成功加载时，登录按钮会禁用，页面会显示错误并提供刷新操作。

## 签发验证码

匿名请求 `POST /admin/passport/captcha`，无请求体，成功返回标准业务响应：

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "captcha_id": "<64 位小写十六进制挑战 ID>",
    "image": "data:image/png;base64,<图片内容>",
    "expires_in": 120
  }
}
```

`captcha_id` 必须匹配 `[a-f0-9]{64}`，`image` 必须为 PNG 的 base64 data URI，`expires_in` 是不大于 600 的正整数秒数。客户端会校验这些字段，不接受缺失字段或不符合契约的响应。示例中的占位文字需要替换为实际生成的值。

后端应生成随机挑战、设置有效期、限制签发和校验频率，并保存答案摘要；接口不能返回明文答案。挑战应在凭据校验之前原子消费，答错也不能重复尝试同一个挑战。多实例后端需要共享挑战存储。

## 提交登录

`POST /admin/passport/login` 的请求体包含四个必需字段：

| 字段         | 含义                  |
| ------------ | --------------------- |
| `username`   | 用户名                |
| `password`   | 密码                  |
| `captcha_id` | 本次签发的挑战 ID     |
| `code`       | 用户输入的 4 位验证码 |

前端不会在浏览器内判断答案是否正确。后端校验验证码及凭据，成功后沿用现有 `access_token`、`refresh_token`、`expire_at` 响应契约。

验证码到期后不可提交；刷新图片、重新签发或登录失败都会清空已输入的验证码。加载期间被替换或取消的请求，其迟到结果不能覆盖当前图片。任何登录失败后都需要新挑战，避免重用已消费的验证码。

## 扩展调用方

`LoginParams` 和 `LoginFormValues` 均要求传入 `captcha_id` 与 `code`。复用 `LoginForm` 的扩展会收到完整的四字段载荷；直接调用会话 `login()` 的扩展需要自行完成挑战获取和用户输入。Token 刷新及使用 `loginWithTokens()` 的独立认证方式沿用各自原有契约。

服务端需要根据实际部署拓扑配置来源识别及限流，不能无条件信任客户端提供的转发头。
